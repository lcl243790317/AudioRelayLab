AudioRelayLab — 真机测试协议与通话稳定性回归

一、目标与已有证据
目标：公开 iOS 音频 API 的未来调度、后台行为、声学再收录以及不可用环境的安全处理。
主设备此前为 iPhone / iOS 18.1.1。每轮填写型号、iOS、微信版本、App build / commit、
签名方式、测试日期、配置 / 引擎、系统音量、App 音量、实际路由和操作时间。

已有用户真机观察（旧版本，不是本轮已验证结果）：
- A 在普通微信语音消息录制中有成功收录，含本人讲话与预设音频共同收录。
- App 音量降到约 4% 后声音明显变小；音量控制应继续保留。
- 微信实时语音通话 / 系统电话下 A / C / D 无法实现目标播放。
- 通话已开始后切回 App，选择 C 并点击准备曾闪退。
- D 普通环境曾运行，但此前实际路由为内置扬声器 / 麦克风，不能判定蓝牙已验证。

新版本尚需按本协议进行真机回归。真实 Xcode build success 只证明构建，
模拟器和 mock 单元测试不能证明 C 通话准备不会在真机闪退。

声学路径：本 App → iOS 音频系统 → 扬声器 → 空气 → 麦克风 → 微信语音消息。
调度被接受、播放器时间线推进、扬声器可听与微信收录必须分别记录。
不把微信实时通话中“必须成功播放”作为目标或通过标准。

二、设备与参数准备
1. 首轮关闭蓝牙 / AirPlay，断开耳机、USB 和外接音频。
2. 核对首页实际 input / output；playback 输入为空是合法的，不代表微信无麦克风。
3. 手动设置并记录系统音量；App 只显示系统音量，不修改。
4. 初始 App 音量 50%，默认测试音约 11.7 秒、44.1 kHz、单声道。
5. 延迟 5 秒，duration 为完整音频；另测明确的 5 秒时长。
6. 新配置选择器仅 A / C / D / E。B 只用于历史兼容。
7. 用自己控制的测试聊天，避免分享他人的电话、讲话和私人内容。
8. 若测试音太响，降低 App 或系统音量再开始，记录变化。

三、测试矩阵
每格至少 3 次；两种引擎分别执行。D 另分无蓝牙与连接 HFP 设备两轮。
环境                 | A | C | D | E | 主要判定
普通前台 / 后台       | ✓ | ✓ | ✓ | ✓ | 听觉、时长、停止、路由、状态、完整诊断
微信语音消息录制       | ✓ | ✓ | ✓ | ✓ | 手动回听收录与本人讲话、音量、系统中断
微信实时语音通话       | ✓ | ✓ | ✓ | ✓ | 即使不能播放也不闪退、合理诊断、结束后可重试
系统电话              | ✓ | ✓ | ✓ | ✓ | 同上，安全处理高优先级音频环境

实时通话的通过标准：
- App 不闪退 / 卡死；准备被阻止或激活被拒绝时安全结束。
- 状态显示“实验失败 / 被系统中断 / 已取消”等对应结果，不停留在假播放。
- 提示当前音频环境不可用，不能把“不知道具体 App”描述成已识别微信。
- 日志有准备 / 激活请求与结果、路由、错误摘要、interruptions、结束状态。
- 系统未建议恢复时不恢复；允许时只有限 best effort；失败后不反复重试。
- 电话 / 微信通话结束后，可手动重新准备 A / C / D / E。
- 不能把未发声或未收录填成成功。

四、普通环境流程
1. 选测试音、A、AVAudioPlayer、5 秒延迟、完整时长、50% App 音量。
2. 点击“准备实验”，确认准备中 → 已准备；此时没有开始未来播放。
3. 点击“开始实验”，确认等待播放 → 可观察播放 → 完成。
4. 在前台听三组测试音，查看未来调度和可观察时间线，不把回调当作声学起点。
5. 改 AVAudioEngine 重复，再对 C / D / E 分别重复。
6. prepared、waiting、playing 阶段分别取消 / 停止，确认旧回调不会恢复播放。
7. prepared 后切后台，核对本轮是保留准备还是安全取消，以实际状态 / 日志为准。
8. waiting / playing 后切后台、锁屏再返回，记录实际发声与状态差异。
9. duration 设为 5 秒核对两套引擎约 5 秒停止；nil 恢复完整音频。
10. 音量分别 0%、4%、50%、100%（合适系统音量下），区分现场听感与录音回听。

五、普通微信语音消息流程
1. 固定 A + AVAudioPlayer + 5 秒延迟 + 完整测试音 + 50%。
2. 准备成功后开始，立即切到测试聊天，在预计播放前按住语音消息按钮。
3. 保持安静，记录现场是否发声；等待测试音结束后松开并回听。
4. 记录完整 / 部分 / 较小 / 未收录、本人讲话、首秒变化、录音被中断等。
5. 返回 App，填写结果和备注，在诊断页导出 TXT / JSON，在历史页导出 JSON。
6. 固定系统音量，对 App 4%、50% 做对比；不要混淆系统输出音量与 App 音量。
7. A 重复稳定后导入真实人声，加入固定本人讲话句子并回听。
8. 按矩阵对 C / D / E 与两引擎重复，保留所有失败记录。
9. C / D 扬声器覆盖开 / 关分别测；“关闭覆盖”不表示 defaultToSpeaker 选项消失。
10. Engine 语音优化开 / 关分别测，只改变该参数，记录清晰度与音量。

六、最高优先级 C 通话准备回归（release blocker）
分别对系统电话和微信实时语音通话，两种引擎各至少 3 次：
1. 先开始真实电话或微信实时语音通话，确认对方仍在通话中。
2. 切回 AudioRelayLab。
3. 选择 C。
4. 点击“准备实验”。
5. 如果已阻止或失败，确认合理提示、技术详情与可保存的失败记录。
6. 如果系统允许准备，点击“开始实验”，观察安全中断或终止，不要求成功播放。
7. 保持通话并多次进出 App，避免无限重试；取消 / 停止后不得自己重新播放。
8. 结束通话，再准备并开始 A，确认正常；接着复测 C / D / E。
9. 导出本轮日志、历史 JSON，记录确切时间与所有设备 / OS / build 信息。

必须：不闪退、合理失败状态、诊断完整、结束通话后可恢复使用。
未执行或发生一次闪退 / 卡死即未通过，不可标为稳定发布。
若仍闪退，应提供对应系统 .ips crash report 和发生时间，保留旧日志，
不凭无栈日志编造唯一根因。

七、通话与中断时序
对 A / C / D / E：
- 通话已开始 → prepare；
- 已准备 → 通话开始 → start；
- 等待播放 → 通话开始；
- 正在播放 → 通话开始；
- 中断期间用户停止 → interruption end；
- interruption end 无 shouldResume；
- 允许恢复但再次激活被拒绝；
- 恢复尝试失败后通话结束 → 用户手动重试。
核对 interruption begin / end 时间、options、route 前后、category、mode、sampleRate、
IO buffer duration、player / engine 状态、恢复次数、最终状态和资源清理。
不得在拒绝激活后持续 setActive，不要求系统替 App 保证播放。

八、蓝牙 / 路由 / 媒体服务
D 无蓝牙时应显示 HFP 已允许、实际内置路由。
连接真实 HFP 设备后，核对 availableInputs 与 currentRoute 的 BluetoothHFP 类型；
设备连上并不等于当前音频使用它，记录实际路由。
准备、等待、播放时分别断开 / 接入蓝牙或耳机，验证无效路由安全终止和重试。
E 分别测静音开关与锁屏，不能把 ambient 的系统限制误当作调度成功。
媒体服务 reset 无法按普通 UI 可靠制造；有可复现方式时另测，否则标“未真机验证”。
模拟故障测试只证明状态处理逻辑，不能冒充真实媒体服务 reset 观察。

九、旧历史与数据回归
使用升级前真实 JSON（A / B / C / D / E）：
1. 导入历史 JSON，应保留真实记录、结果、备注、UUID 和旧 settings。
2. B 显示“B（旧版普通播放，已停用）”，新选择器不能选 B。
3. 查看 B 详情，导出 JSON 再导入，无崩溃。
4. unknown enum、缺字段和单条损坏输入应提示恢复 / 跳过，正常记录仍可查看。
5. 重复导入核对 UUID 去重，不丢失原有历史。
6. 保存实验、强制退出、再启动，核对日志草稿与状态，勿把未检查记录自动改成功。
7. 真机历史导入的文件 IO 与授权失败需友好处理。

十、日志、结果与证据保留
每条日志含时间戳、单调 uptime、实验 ID、sequence、category、message。
TXT / JSON 导出当前显示日志；清空页面不删实验审计日志，历史保存完整本轮记录。
JSON 历史含 settings、requestedDuration、设备 / OS、会话快照、结果、人工备注和错误。
用户结果保留成功、失败、不确定、未检查等真实判断；自动事件不代替人工回听。
自动日志去掉 UID 和私人端口名；导入审计按本轮要求含文件名、原 URL 与目标，
旧历史、个人路径和人工备注需分享前检查。

Windows 分析：
python scripts/analyze-log.py <日志.txt 或历史.json 或诊断.jsonl>
分析工具只汇总真实事件，不自动判断微信是否收录。
真实请求时间、调度调用、目标音频时间、可观察时间、实际发声与微信回听分别判读。
每轮最终证据包括 commit / build、实验 UUID、日志、JSON 和人工结果。
CI run / xcodebuild / IPA SHA 记录在 BUILD-STATUS-ZH.txt，不能代替本协议。
