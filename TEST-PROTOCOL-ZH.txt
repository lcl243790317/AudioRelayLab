音频接力实验室 — 真机测试协议

目标：验证公开 iOS 音频 API 的未来调度、后台行为、音频会话抢占与同机声学再收录。
主设备：iPhone / iOS 18.1.1。测试前填写具体型号、微信版本、签名方式和测试日期。
数据路径：本 App → iOS 音频系统 → iPhone 扬声器 → 空气 → iPhone 麦克风 → 微信录音。
成功或失败都属于有效结果。不要把播放回调或调度成功当作微信录入证据。

一、第一轮设备状态
关闭蓝牙；断开 AirPods；拔掉耳机；移除 USB / 外接音频；关闭 AirPlay 输出。
使用 iPhone 自带扬声器和麦克风。路由应看到 BuiltInSpeaker，输入可能为空或 BuiltInMic。
playback 配置本身不启用输入，因此输入路由为空不能说明微信无法使用麦克风。
不要选择其他外部音频设备。App 检测外部路由会显示黄色提示并记录端口类型、名称和 UID。
手动设置并记录系统音量；App 的播放音量只控制播放器，不改变系统音量。
关闭静音开关做第一轮，E / Ambient 可另测静音开关和锁屏影响。
先确认微信中准备使用的测试聊天，可使用自己控制的测试对话。

二、前台控制实验（每种引擎至少一次）
1. 打开 App，点击“使用测试音频”。确认时长约 11.7 秒、44,100 Hz、单声道。
2. 选 AVAudioPlayer、A / 播放 + 混音、3 秒、50%。
3. 点击“准备并开始”，留在前台，听到三组 440 / 660 / 880 Hz 测试音。
4. 查看诊断：调度调用、目标设备时间、返回值、可观察时间线推进、完成回调。
5. 保存结果，备注“前台控制实验”。
6. 改为 AVAudioEngine 重复，查看 hostTime 调度、playerSampleTime 与 dataPlayedBack。
7. 验证停止按钮：目标时间之前停止，以及正在播放时停止，确认没有自动重新开始。

三、基准微信实验
配置：A / 播放 + 混音，AVAudioPlayer，延迟 3 秒，播放音量 50%。
1. 打开音频接力实验室。
2. 点击“使用测试音频”。
3. 选择 AVAudioPlayer。
4. 选择 A / “播放 + 混音”。
5. 延迟设为 3 秒。
6. 播放音量设为 50%。
7. 点击“准备并开始”；此时 App 在前台已完成音频系统未来时间调度。
8. 立即切到微信。
9. 进入已准备好的测试聊天。
10. 从点击开始约第 2 秒按住语音消息录音按钮。
11. 保持安静，尽量不遮挡手机麦克风或扬声器。
12. 等待测试音频预计结束（点击开始后约 15 秒）。
13. 松开录音按钮。
14. 播放刚才的微信语音。
15. 判断是否包含完整、部分、明显变小或完全没有测试音。
16. 返回 AudioRelayLab。
17. 点击“保存实验结果”，选择真实结果并写备注。
18. 在诊断页导出日志，并在历史页导出 JSON。
备注记录：是否实际听见扬声器、微信语音含多少组音、微信录音是否被中断、操作时间偏差。

五、本人讲话与预设音频共同收录
先找到稳定、重复可复现的组合，再使用实际人声文件。
先导入一段短 M4A / WAV / MP3 / AAC，确认 Sandbox 副本元数据与前台播放。
按基准流程按住微信录音，在预设音频期间说固定句子，例如“这是本人同时讲话的测试”。
回听确认预设内容和自己的声音是否都出现，是否产生回声、压缩、降噪或音量降低。
不要用一次结果推广到所有手机、微信版本或 iOS 版本。

六、中断与状态实验
分别在目标时间前和播放中启动微信录音，记录 interruption began / ended / shouldResume。
只有系统提供 shouldResume、用户未停止、播放器处于可恢复状态时，App 才尝试恢复。
AVAudioEngine 停止会清除队列；恢复从最后可观察帧重新调度，日志明确说明这是新尝试。
恢复成功不等于原始后台调度连续执行。
测试中按“停止播放”，再触发音频中断结束，确认用户停止优先，不自动恢复。
前后台切换、路由连接/断开、媒体服务丢失/重置和引擎配置变化都应留下诊断。
媒体服务重置后需手动重新开始，不自动重做实验。

七、日志判读与导出
请求时间：用户开始实验的前台请求；权限对话结束后才开始记录本次实验。
调度调用时间：真正调用音频 API 的时间。
目标音频时间：设备音频时钟或 hostTime 上的计划值。
可观察播放开始：前台 250 ms 采样第一次看到时间线推进的时刻，可能明显晚于实际发声。
后台可能不执行 UI 定时器；不通过定时器触发播放。
无法直接确认实际扬声器起始时间。没有观察事件不证明没有播放；有观察事件不证明微信收录。
完成回调证明音频系统报告完成，微信收录以回听为准。
JSON 含固定配置、设备信息、结果、备注和完整日志；CSV 对公式起始字符作转义保护。
日志每条含毫秒本地时间、单调 uptime、启动后经过秒数、事件类别与消息。
清空诊断页面只改变显示边界，不移除当前实验完整日志。
历史会在开始、生命周期、状态变化和填写结果时保存；强制终止仍可能丢失最后尚未写入的事件。
Application Support/Diagnostics 下保留每次启动的 JSONL；在支持 App 文件访问的本地工具中可获取。
诊断可能含自己导入的文件名、路由名称、UID 和备注，按自己的需要选择分享目标。

Windows 分析导出的日志：
python scripts/analyze-log.py <日志.txt 或历史.json 或诊断.jsonl>
该工具只汇总真实事件，不自动判断微信是否收录。

八、麦克风注入诊断
iOS 18.1.1 显示“当前系统低于 iOS 18.2，不支持此诊断能力”。
支持该 API 的构建在 iOS 18.2+ 仅读取 isMicrophoneInjectionAvailable。
能力为“是”也不意味着微信录音允许此行为。本项目不启用注入，核心实验完全独立。

九、结果分类
音频成功进入微信语音 / 播放被停止 / 播放继续但微信没有录进去 /
播放音量明显降低 / 微信录音被中断 / 不确定。
结果只由用户回听与真机观察填写；自动诊断草稿默认“不确定”，标明尚未判断。
保留失败日志。比较相同设备、同一 iOS/微信版本、相同系统音量与操作条件的重复实验。
